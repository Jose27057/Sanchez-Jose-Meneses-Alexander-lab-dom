DOM, eventos y validación de formularios en JavaScript

Vas a manipular una página desde JavaScript, reaccionar a lo que hace el usuario y validar un formulario con mensajes claros y accesibles. Cada parte trae código comentado, una demo que puedes probar aquí mismo y una pregunta de control.

Duración: 2 sesiones de 90 min Requisitos: HTML, CSS, variables y funciones en JS Herramientas: VS Code, navegador con DevTools (F12)

Objetivos de aprendizaje

Al terminar el laboratorio podrás:

  • Seleccionar elementos con querySelector y querySelectorAll, y cambiar su texto, clases y atributos.
  • Crear y eliminar nodos con createElement, append y remove.
  • Registrar manejadores con addEventListener, leer el objeto event y usar delegación de eventos.
  • Validar un formulario combinando atributos HTML5, la API de validación del navegador y reglas propias en JS.
  • Mostrar errores accesibles con aria-invalid, aria-describedby y aria-live.

Parte 1El DOM

El DOM (Document Object Model) es la representación en memoria de tu HTML como un árbol de objetos. Cada etiqueta es un nodo que JavaScript puede leer y modificar. Si cambias el DOM, el navegador vuelve a pintar la página.

1.1Seleccionar elementos

app.js
const titulo = document.querySelector('#titulo');     // primer elemento que coincide
const items  = document.querySelectorAll('li');     // NodeList con todos

console.log(titulo.textContent);
items.forEach(li => console.log(li.textContent));

querySelector acepta cualquier selector CSS: '.tarjeta', 'form input[type=email]', '#menu > li:first-child'. Si no encuentra nada devuelve null.

1.2Cambiar texto, clases y atributos

app.js
titulo.textContent = '¡Hola DOM!';          // texto seguro
titulo.classList.add('destacado');          // add / remove / toggle / contains
titulo.setAttribute('title', 'Encabezado');
titulo.dataset.estado = 'activo';           // crea data-estado="activo"
titulo.style.color = 'steelblue';            // estilo en línea (úsalo poco)
textContent vs innerHTML. innerHTML interpreta HTML. Si le pasas algo que escribió el usuario, puede inyectar código (XSS). Para mostrar datos del usuario usa siempre textContent.

1.3Crear y eliminar nodos

app.js
const lista = document.querySelector('#lista');
const lenguajes = ['HTML', 'CSS', 'JavaScript'];

for (const nombre of lenguajes) {
  const li = document.createElement('li');
  li.textContent = nombre;
  lista.append(li);                         // lo agrega al final
}

lista.lastElementChild.remove();           // elimina "JavaScript"

Parte 2Eventos

Un evento es una señal de que algo pasó: un clic, una tecla, un cambio en un campo, el envío de un formulario. Registras una función (manejador) que el navegador ejecuta cuando ocurre.

2.1addEventListener y el objeto event

app.js
const boton = document.querySelector('#saludar');

boton.addEventListener('click', (event) => {
  console.log(event.type);     // "click"
  console.log(event.target);   // el elemento que recibió el clic
});

document.addEventListener('keydown', (e) => {
  if (e.key === 'Escape') console.log('Cerrar modal');
});
EventoCuándo ocurreUso típico
clickClic o Enter/Espacio sobre un botónAcciones, menús
inputCada vez que cambia el valor de un campoValidación en vivo, contadores
changeAl confirmar el cambio (select, checkbox, salir del campo)Filtros, opciones
blur / focusEl campo pierde o gana el focoValidar al salir del campo
keydownSe presiona una teclaAtajos, juegos
submitSe envía un formularioValidación final

2.2Delegación de eventos

En vez de poner un manejador en cada botón de una lista, pones uno solo en el contenedor. Los eventos “burbujean” desde el elemento pulsado hacia arriba, y con event.target.closest() averiguas qué se pulsó. Funciona incluso con elementos creados después.

app.js
const lista = document.querySelector('#tareas');

lista.addEventListener('click', (e) => {
  const borrar = e.target.closest('.borrar');
  if (borrar) {
    borrar.closest('li').remove();
    return;
  }
  const texto = e.target.closest('.texto');
  if (texto) texto.closest('li').classList.toggle('hecha');
});

2.3preventDefault

Algunos elementos tienen un comportamiento por defecto: un formulario recarga la página al enviarse, un enlace navega. event.preventDefault() lo cancela para que tu código decida qué hacer.

app.js
form.addEventListener('submit', (e) => {
  e.preventDefault();                // no recargar la página
  const datos = new FormData(form);
  console.log(Object.fromEntries(datos));
});

    Parte 3Validación de formularios

    Validar en el cliente mejora la experiencia: el usuario corrige antes de enviar. No reemplaza la validación en el servidor, porque cualquiera puede saltarse el JavaScript. Trabajaremos en tres capas.

    3.1Capa 1: atributos HTML5

    index.html
    <form id="registro" novalidate>
  <label for="correo">Correo</label>
  <input id="correo" name="correo" type="email" required
         aria-describedby="correo-error">
  <p id="correo-error" class="error" aria-live="polite"></p>

  <label for="cedula">Cédula</label>
  <input id="cedula" name="cedula" required
         pattern="([1-9]|1[0-3]|PE|E|N)-\d{1,4}-\d{1,6}"
         placeholder="8-123-4567">
</form>

    required, type="email", minlength, min/max y pattern ya describen las reglas. El atributo novalidate desactiva las burbujas nativas del navegador para que tú muestres los mensajes con tu propio diseño, pero las reglas siguen disponibles desde JS.

    3.2Capa 2: API de validación del navegador

    app.js
    const correo = document.querySelector('#correo');

correo.checkValidity();          // true / false
correo.validity.valueMissing;     // true si required y está vacío
correo.validity.typeMismatch;     // true si no parece un correo
correo.validity.patternMismatch;  // true si no cumple pattern
correo.validity.tooShort;         // true si no llega a minlength

// Marcar un error propio (cadena vacía = válido)
correo.setCustomValidity('Ese correo ya está registrado');

    3.3Capa 3: reglas propias, reutilizables

    Guarda las reglas en un objeto: cada función recibe el valor y devuelve true o el mensaje de error. Así una sola función validarCampo sirve para todos los campos.

    app.js
    const reglas = {
  nombre: v => v.trim().length >= 3 || 'Escribe al menos 3 caracteres.',
  correo: v => /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(v) || 'Usa un correo como nombre@dominio.com.',
  cedula: v => /^([1-9]|1[0-3]|PE|E|N)-\d{1,4}-\d{1,6}$/.test(v) || 'Formato: 8-123-4567.',
  clave:  v => (v.length >= 8 && /[A-Z]/.test(v) && /\d/.test(v))
               || 'Mínimo 8 caracteres, una mayúscula y un número.',
  clave2: v => v === form.clave.value || 'Las contraseñas no coinciden.',
};

function validarCampo(input) {
  const resultado = reglas[input.name](input.value);
  const valido = resultado === true;
  const error = document.getElementById(`${input.name}-error`);

  input.setAttribute('aria-invalid', String(!valido));
  error.textContent = valido ? '' : resultado;
  return valido;
}

    3.4Cuándo mostrar los errores

    Mostrar un error rojo mientras la persona apenas empieza a escribir es molesto. Un patrón que funciona bien:

    1. Valida un campo la primera vez al salir de él (blur) y márcalo como “tocado”.
    2. Desde ese momento, revalídalo en cada tecla (input), para que el error desaparezca apenas se corrige.
    3. Al enviar (submit), valida todo y lleva el foco al primer campo con error.
    app.js
    const form = document.querySelector('#registro');
const tocados = new Set();

form.addEventListener('blur', (e) => {
  if (!reglas[e.target.name]) return;
  tocados.add(e.target.name);
  validarCampo(e.target);
}, true);   // true = fase de captura (blur no burbujea)

form.addEventListener('input', (e) => {
  if (tocados.has(e.target.name)) validarCampo(e.target);
});

form.addEventListener('submit', (e) => {
  e.preventDefault();
  const campos = [...form.elements].filter(el => reglas[el.name]);
  const invalidos = campos.filter(el => !validarCampo(el));
  if (invalidos.length) { invalidos[0].focus(); return; }
  mostrarResumen(new FormData(form));
  form.reset();
});

    Pregunta de control 3

    ¿Por qué el manejador de blur se registra con true como tercer argumento?

    Respuesta: blur no burbujea. Con true el formulario lo escucha en la fase de captura (de arriba hacia abajo), así que un solo manejador en el <form> sirve para todos los campos. Otra opción es usar focusout, que sí burbujea.
